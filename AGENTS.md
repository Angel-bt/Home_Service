# AGENTS.md

## Layout

- The application lives in `laravelhomeservices/`; tutorial notes/links live in `laravelhomeservices/pasos .txt`. Run every app command from `laravelhomeservices/`. The repo root only holds this folder plus `README.md`, `AGENTS.md` and git/editor config.
- Laravel 13 + Livewire 3 full-page components + Jetstream 5/Fortify auth + Sanctum 4 + Tailwind (via Mix). PHP `^8.3`. The favicon is `public/images/favicon.png`.
- The app keeps the pre-Laravel-11 structure (`app/Http/Kernel.php`, `app/Console/Kernel.php`, `RouteServiceProvider`, `Exceptions/Handler`); Laravel 13 still supports it. Register middleware in `Kernel::$middlewareAliases`.

## Local dev

- `.env`: MySQL db `home` (root/root) and Redis for `CACHE/SESSION/QUEUE` (`phpredis`). A local Redis instance is required for `php artisan serve`; tests are not (see below).
- Assets use **Laravel Mix** (`webpack.mix.js`), not Vite: `npm run dev` / `npm run watch` / `npm run prod`. `layouts/base.blade.php` and `layouts/landing.blade.php` load only `mix('css/app.css')`; Tailwind `preflight` stays disabled (own reset under `body.lp`). Rebuild after adding Tailwind classes to views.
- `php artisan db:seed --class=DemoMarketplaceSeeder` (local only) creates Spanish local categories, demo admin/providers/customer (`*@proyetech.test`, see the seeder) and a completed request with a review.
- Timezone is `America/Guayaquil` (`APP_TIMEZONE`); timestamps are stored in local time. Locale is `es` (`APP_LOCALE`); Spanish strings live in `lang/es/*.php`, untranslated validation keys fall back to `lang/en`.
- SMTP points at Mailpit-style `127.0.0.1:1025`.
- `/change-location` loads Google Places only when `GOOGLE_MAPS_API_KEY` is set (`config('services.google_maps.key')`); without it the page shows a warning and manual fields.

## Tests

- `php artisan test` (or `vendor/bin/phpunit`, PHPUnit 12: use `#[DataProvider]` attributes with static providers, not docblock annotations). `phpunit.xml` overrides to sqlite `:memory:`, array cache/session, sync queue — no MySQL/Redis needed.
- `tests/Unit` holds pure-logic tests (WhatsApp, request transition matrix, plan rules, service visibility/price, badges, text helpers, `SiteSettings`). `AdminCatalogAndPermissionsTest` calls every admin Livewire action as `SVP` and `CST` and expects 403: when you add an admin action, put `abort_unless(Auth::user()?->utype === 'ADM', 403)` in it and add it to that data provider.
- Besides stock Jetstream tests, `tests/Feature/MarketplaceSmokeTest.php` renders every public/admin/provider/customer page and covers registration roles. `tests/Feature/MarketplaceFlowTest.php` covers provider publishing/freemium, profile zones, the request → review flow, search and zone filters. `ServiceDetailsComponent` swallows (and reports) visit-counter failures, so `/service/{slug}` renders without Redis.

## Domain model and roles

- `users.utype`: `ADM` (admin), `SVP` (service provider), `CST` (customer). Guards are the `authadmin` / `authsprovider` middleware; a mismatch redirects to the user's own panel (`User::dashboardRoute()`) with `session('error')`, without signing out. After login/registration, `RoleHomeResponse` sends `ADM`/`SVP` to their panel. Create an `ADM` user directly in DB.
- Register validates `registeras` as `CST|SVP` (missing → `CST`); `SVP` also creates the `service_providers` row. Deleting a category nulls `service_providers.service_category_id` (does not delete the profile).
- The global visit counter is the first `visit_counter` row from `Visit::counter()` (whatever its id: looking up `id = 1` created a new row per visit when that id was missing). `visitor_name` is NOT NULL.
- Providers (`SVP`) manage their own services under `/sprovider/my-services` (not `/sprovider/services`: it would collide with the public `/{category_slug}/services`). Admin and provider service forms share `App\Http\Livewire\Concerns\HandlesServiceForm` (rules, uploads, `|`-joined inclusion/exclusion) and the `livewire.partials.service-form` view.
- Zones are slugs from `config('marketplace.zones')` (only `malacatos` — the main zone, `marketplace.main_zone` — `vilcabamba`, `yangana`, `quinara`) stored in `provider_zones`; `Service::scopeInZone()` returns services of providers covering the zone plus services not owned by an `SVP` (admin services count for every zone). Listings remember the chosen zone in `session('zone')` via `Concerns\FiltersByZone`.
- `service_requests` flow: `pending` → `accepted`/`rejected` (provider or ADM) → `completed` (provider); customer may cancel `pending`/`accepted`. Transitions are enforced only in `ServiceRequest::transitionTo()`. Reviews: one per completed request, by its customer (`ServiceRequest::canBeReviewedBy()`).
- WhatsApp links go through `App\Support\WhatsApp` (normalises Ecuadorian numbers to `593…`). Provider number = `service_providers.whatsapp`, else `users.phone`; non-provider services use `marketplace.contact_phone`.
- Freemium cap: `FREE_SERVICE_LIMIT` (default 3) services for `free` plan; `ADM` and `User::isPro()` unlimited. Enforced by `ServicePublicationGate` on create; `User::canPublishService()`. `isPro()` also checks `plan_expires_at`, so an expired plan stops counting before `billing:expire-plans` runs.
- Pro plan billing (no Stripe: it doesn't serve Ecuador): only bank transfer and cash for now (`SubscriptionPayment::MANUAL_METHODS`). Transfer = provider uploads a receipt to the private `receipts` disk; cash = provider notifies without receipt, or the admin records cash received (`AdminPaymentsComponent::recordCashPayment`, approved at once). Pending payments are approved/rejected in `/admin/payments`. Payphone card payments (`PayphoneGateway`, `BillingController`) exist but are off unless `PAYPHONE_ENABLED=true`; `deuna` is a legacy method label only. Always change plan state through `App\Services\ProPlanBilling::approve()/reject()` (idempotent, extends from current expiry). Payphone payments start as `initiated` and are approved only after a server-side Confirm matching `clientTransactionId` and amount; `/billing/payphone/return` is intentionally unauthenticated. Tests fake Payphone with `Http::fake()`.

- Registration is two steps (`components/site/register-form`): account type + terms summary + checkboxes, then data; `CreateNewUser` re-validates `terms` and `publication_consent` (required for `SVP`) and records `terms_version`, `terms_accepted_at`, `publication_consent_at`. `EnsureTermsAccepted` (web group, skips `ADM`, non-GET, JSON) redirects accounts on an older version to `/aceptar-terminos`. Bump `marketplace.terms_version` when the terms change materially; don't change the published consent text without bumping it. Factories default to the current version.
- Provider verification is deliberately voluntary (LOPDP art. 4, 8, 26; Constitution art. 11.2; see `docs/01` Fase 8): never make it a condition to publish, and never show anything public about a provider without a badge or with a rejected document. Types live in `ProviderDocument::TYPES`; change badges only through `App\Services\ProviderVerification`, which stores files on the private `receipts` disk and deletes them once reviewed. `ServiceProvider::badgeFor()/trustBadges()/isVerified()` read the public state; the background badge expires (`background_valid_until`).
- Activity goes through `App\Support\Activity::record()/forService()` into `activity_events` (`/admin/activity`, CSV export): it swallows failures, skips bots, `ADM` and owners viewing their own services, and stores no IP or message text. `SearchComponent` merges a term typed letter by letter into one row. WhatsApp buttons on service pages link to `home.service_whatsapp`, which counts the click and redirects. `activity:prune` runs in the daily cron; the retention period is promised in the privacy policy.
- `tests/Feature/SiteCrawlTest.php` crawls every internal link per role on the demo data and fails on 4xx/5xx, missing local images, `src=""` and pages using the generic tab title: give every page a title (`->title()` on Livewire, `<x-base-layout title="…">` in Blade). `/sitemap.xml` (`SitemapController`) lists public pages and active services; `public/robots.txt` hardcodes the production URL.
- Admin-editable settings: `App\Support\SiteSettings` (table `settings`, cached `site:settings`) overrides `config()` at boot for contact, plans, bank, verification days and zones; keep reading `config()` elsewhere and add new editable values to `SiteSettings::FIELDS`. FAQ lives in `faqs` (`/admin/faq`, placeholders in `Faq::PLACEHOLDERS`), not in Blade.
- Public visibility of a service = `status` (admin hide) AND `paused_at` null (provider pause) AND owner not suspended: use `Service::scopeActive()` / `isPublic()`. Details pages show hidden services only to the owner and `ADM`. Suspended users (`users.suspended_at`) are blocked at login (`FortifyServiceProvider`) and logged out by `EnsureNotSuspended`. `Service::reviews()` excludes `hidden_at` reviews. `DeleteUser` deletes the user's services (the FK only nulls `user_id`, which would make them look like admin services).
- Admin menu items in `x-ui.panel` take a 6th element (section label). Admin list actions on services are shared through `Concerns\ManagesServicesAsAdmin`.
- E-mails to people go through `App\Support\Notice::send()` (never throws). `ServiceRequest::transitionTo()` notifies the other party; new requests call `notifyProviderOfNewRequest()`.

## Gotchas

- Livewire 3: components stay in `App\Http\Livewire` (`config/livewire.php` `class_namespace`), default layout `layouts.base`. `wire:model` is deferred; use `wire:model.live` for inputs that must re-render (zone/status/period selects, search with `.live.debounce`), `.blur` instead of v2 `.lazy`. Events: `$this->dispatch(...)->to(...)`. Every component view needs exactly one root element (put `<script>`/`<style>` inside it or in `@push('scripts')`).
- `AuthAdmin`/`AuthSprovider` are Livewire persistent middleware (`AppServiceProvider`), so role checks also run on `/livewire/update` requests.
- Jetstream 5 views/components are published (`resources/views/components`, `x-button`, no `x-jet-` prefix). Unused scaffolding was removed (`dashboard`, `navigation-menu`, `layouts/guest`, `terms`/`policy`): the site has its own `/terms` and `/privacy`, so don't enable `Features::termsAndPrivacyPolicy()`. `layouts/app.blade.php` wraps `<x-base-layout>` so account pages (`/user/profile`) use the site header; there is no `dashboard` route. Jetstream strings are translated in `lang/es.json`. Tailwind `darkMode: 'class'` keeps Jetstream's `dark:` styles off.
- Password reset uses Fortify only (`/forgot-password`, `password.request`); `NeutralPasswordResetLinkResponse` answers unknown e-mails like sent links. Don't re-add custom routes with Fortify's names: duplicate names break `route:cache`.
- Sessions use JSON serialization and `cache.serializable_classes` is `false` (no objects are ever unserialized from the cache). Cache arrays/scalars only; caching objects requires listing their classes there.
- Livewire actions that send data (contact, service request, Pro receipt) are rate limited with `Concerns\ThrottlesActions`; route `throttle` does not cover `/livewire/update`.

- `AdminServicesByCategoryComponent` is now only served by the `authadmin` route `/admin/{category_slug}/services`; its `deleteService()` also re-checks `Auth::user()->utype === 'ADM'`. The former public `servicesbycategory/{category_slug}` route was removed — public category links use `home.services_by_category` (`/{category_slug}/services`).
- All inner pages use `layouts.base` (no jQuery/Bootstrap/Font Awesome). Build screens from `components/ui/*` and the `ui-*` classes in `resources/css/app.css`: `x-ui.panel` (role menu, title, one-line help, flash) for every panel page, `x-ui.page` for public pages, `x-ui.field`, `x-ui.status`, `x-ui.empty`, `x-ui.checklist`. Users are non-technical: every screen says what to do next, every empty list offers a next step, errors explain the fix (`lang/es/validation.php`), destructive actions use `wire:confirm` (on the `<form>` for forms). `request()->routeIs()` is wrong during `/livewire/update`; see how `x-ui.panel` uses `Livewire::originalUrl()`. Deleting a category cascades to its services.
- Photo uploads use `x-ui.photo-input` (shrinks images in the browser: phone photos exceed the 4 MB limit and Vercel has no GD) with `ui-submit` on the save button. The service form requires only name, category, price, one photo and description; the thumbnail falls back to the same photo. Emails are lowercased (`fortify.lowercase_usernames`) because Postgres is case-sensitive.
- Public images go through `App\Support\Media` (`url/store/delete`), never `asset('images/...')` or a bare `storeAs`. Livewire temp uploads use the private `uploads` disk (never under `public/`: they can be payment receipts). Vercel needs no code changes, only env vars (`.env.vercel.example`, `docs/06`): object storage, `database` sessions/cache, `QUEUE_CONNECTION=sync`, `VISIT_COUNTER=database`, `/cron/diario` with `CRON_SECRET`. Since mail can run inline, wrap job dispatches in try/catch and report: a mail failure must not undo the user's action.
- Deployed at https://malakplace.vercel.app (Vercel project `malakplace`, every push to `main` deploys it, Root Directory `laravelhomeservices`; manual deploys run from the repo root; see `docs/06`). Production runs on **Postgres** (Supabase) while local is MySQL and tests are SQLite: avoid engine-specific SQL, and remember Postgres is case- and accent-sensitive. To test on Postgres use a throwaway schema via `DB_SCHEMA`, never `public` (`RefreshDatabase` drops tables). The site is live with real users and no demo data: never run `DemoMarketplaceSeeder` there, and treat its database as production. `php artisan storage:check` (run by the daily cron, which answers 500 on failure) proves both buckets and the signed upload path end to end. `php artisan mail:check` (same cron) logs in to the SMTP server (Gmail app password) without sending anything.
- The platform's public name is **Malakplace** (Proyetech is the company behind it; demo e-mails `*@proyetech.test` keep the old name). Use "Malakplace" in user-facing copy.
- The landing (`HomeComponent`) uses its own layout `layouts.landing` (no jQuery/Bootstrap/Font Awesome) with the "Valle de noche" design (inspired by halo-lab.com): `components/site/*` (header, footer, auth-modal, icon), palette `noche/humo/grafito/oro/menta` (oro is the only accent), `font-body` (Inter Tight) with `lp-title`, and `lp-accent` (Instrument Serif italic) for one key word per heading. `body.lp` reset in `resources/css/app.css` is wrapped in `:where()` so Tailwind utilities always win — keep it. Animations live in `resources/js/landing.js` (GSAP+ScrollTrigger+SplitText+Lenis, own Mix entry) driven by `data-*` attributes; never hide content in CSS, wrap tweens of elements with Tailwind `transition` classes in `calm()`, and keep the reduced-motion "gentle" path working (`?motion=full` forces full motion). The full-width header (`.lp-header`) hides on scroll down and copies `data-tone` (`dark|light`) from the section under it (`headerTone()`), so every landing section needs `data-tone`. Avoid decorative pills/dots on eyebrows and badges. The hero services strip (`data-hero-services`, `ticker` data) moves with pure CSS (`.lp-marquee`, duplicated list, `--lp-marquee-duration`) and intentionally keeps moving (slower) under reduced motion. Its data is one cached array `home:landing` (≤10 min), invalidated on `Service`, `ServiceCategory` and `Review` save/delete. After external edits, `php artisan cache:clear`.
- Public image files are deleted through `App\Services\ServiceAssetCleaner`, which builds absolute paths with `public_path()` (independent of CWD) and skips missing files. Don't reintroduce relative `unlink('images/...')` calls.
- Newer PHP files use `declare(strict_types=1)` + typed signatures; older tutorial-era files do not. Match the file you are editing.
- Visit counts are Redis counters (no DB write per view); `php artisan services:sync-visit-counters` flushes them to `services.views` and is scheduled every 5 minutes.
- Registration/contact dispatch queued mail jobs (queue `mail`, 3 tries). `LEAD_NOTIFICATION_ADDRESS` unset intentionally skips the lead email.
- Human documentation (Spanish) lives in `laravelhomeservices/README.md` and `laravelhomeservices/docs/01..07-*.md` (history/decisions, architecture, flows, payments, security, deployment, development/tests). `docs/06-despliegue-y-operacion.md` is authoritative for schedulers, caching, queues and env vars. Update the relevant doc when you change behaviour.
